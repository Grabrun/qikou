## 0. TL;DR

**v3.0 = 宽召回候选生成 + 统一坐标特征 + LightGBM 二分类 + 概率校准
+ 规则融合 + 动态规划全局打包 + 可监控可回退。**

两条硬约束贯穿全文：

1. **运行时零第三方依赖不能破。** `pip install qikou` 至今只装一个纯
   Python 包，这是项目的核心卖点。解法是**训练用 LightGBM（开发期依
   赖），推理用随包模型 + 纯 Python 评估器**——预研已实测验证：纯
   Python 推理与 LightGBM 输出**逐样本一致**（最大绝对差 1.1e-16）。
2. **模型复杂度是推理预算，不是自由参数。** 树数与叶数直接决定纯
   Python 推理耗时；第 8 章给出实测换算表与上限。

## 1. 目标与设计原则

**目标**：在 v2.2 规则方案基础上引入候选点二分类模型，把切分质量从
规则上限推进到「人工 gold 上边界 F1 ≥ 0.85」，同时保持低风险、可解
释、可回退。

**设计原则**：

1. **规则保底，模型增强** —— 候选生成、特殊片段保护、打包、后处理仍
   由规则负责；模型只决定「切不切」。
2. **坐标统一** —— 原文坐标、保护后坐标、切点标签、特征抽取全部使用
   同一套映射。任何跨越边界的比较都是 bug 来源。
3. **候选宽召回** —— 候选点宁多勿漏，金标召回率 ≥ 99% 才允许训练模型。
4. **概率校准** —— 模型输出必须校准后才能用于融合与阈值判断。
5. **全局打包** —— 推理阶段用动态规划替代局部贪心。
6. **零依赖推理** —— 模型随包分发，用纯 Python 评估器执行，运行时不
   引入 `lightgbm` / `numpy` / `pickle`。
7. **可回退可监控** —— 任何异常自动回退规则路径，模型、特征、数据均
   有版本记录。
8. **合规先行** —— 真实聊天日志必须脱敏、授权、最小化使用。

## 2. 预研结论（实测数据）

在本机（Python 3.14 / LightGBM 4.7.0）实测，用于给第 8 章的预算与第
11 章的验收线定标：

| 项目 | 结果 |
|---|---|
| 候选点密度 | **14.5 个 / 100 字**（现有 `SEPS` 位置） |
| 弱标签正例率 | **10.9%**（约 1:8 不平衡） |
| 训练耗时 | 2 万行 × 40 特征、200 棵树 → **0.3 秒** |
| `dump_model()` | 可解析 JSON；树结构为 `split_feature` / `threshold` / `left_child` / `right_child` |
| **纯 Python 推理精度** | 与 `booster.predict()` 最大绝对差 **1.1e-16**（逐样本一致） |
| 纯 Python 推理速度 | 0.191 ms/候选（朴素字典版）→ **0.096 ms/候选**（扁平数组版，200 树 × 31 叶） |
| 换算 | 500 字（约 72 候选）**6.9 ms**；1000 字约 13.9 ms |
| 折半模型 | 100 树 × 15 叶 ≈ **0.029 ms/候选** → 500 字约 **2.1 ms** |
| C++ 版对照 | LightGBM 原生 0.001 ms/候选（约 100 倍快，但需引入依赖） |
| 模型体积 | 397 KB（200×31）→ 约 200 KB（100×15） |
| **现有语料可用性** | `tests/test.txt` 中位长度仅 **12 字**，是测试集不是训练集，**必须另建语料** |

**结论：技术路线可行，主要风险不在工程，在数据。**

## 3. 总体架构

### 离线管线

```
原始语料
  → 脱敏与合规过滤
  → 坐标映射与保护片段
  → 候选点生成
  → 特征抽取（与在线共用同一模块）
  → 标签对齐
  → LightGBM 训练（开发期依赖）
  → 概率校准
  → 离线评估
  → 模型注册 → 导出为零依赖产物（JSON）
```

### 在线管线

```
用户输入
  → protect_special + 坐标映射
  → 候选点生成
  → 特征抽取（纯 stdlib）
  → 纯 Python 模型推理
  → 概率校准（纯 Python）
  → 规则融合
  → 动态规划打包
  → 后处理
  → 输出多条消息
  → 监控与回退（异常即回落规则路径）
```

## 4. 任务建模

**核心任务**：候选点二分类 + 全局切分决策。

- 输入：一段 AI 回复文本。
- 候选点：所有可能切分的位置。
- 模型输出：每个候选点的**校准**切分概率。
- 最终决策：在长度约束、语义约束、规则分数下，用动态规划选出全局最优
  切分序列。

**候选点定义**：

- 标点后：`。！？!?…`；`;，,、：:`
- 空格后、换行后
- Markdown 块边界：标题、列表项、引用、代码块结束
- URL、代码块、行内代码、公式的外边界
- 中英边界、数字/单位边界
- 长度安全点：每 `max_chars` 附近最近的安全位置

**标签定义**：

- 正样本：候选点属于人工金标切点。
- 负样本：候选点不属于金标切点。
- 所有标签必须映射到**保护后坐标**再与候选点比较；同时保留原文坐标，
  用于最终切分与人工核对。

> 术语：项目面向「**AI 回复**」——AI 在这里指不调用工具、只按规则生成
> 文本的模型。文中不使用「Agent 回复」这一说法。

## 5. 数据方案

### 5.1 数据来源分层

| 层级 | 来源 | 用途 | 置信度 |
|---|---|---|---|
| L1 | LLM 合成切分 | 冷启动 | 中高 |
| L2 | 规则弱监督 + 人工修正 | 快速扩量 | 中 |
| L3 | 真实聊天日志挖掘 | 贴近真实分布 | 高 |
| L4 | 在线隐式反馈 | 持续优化 | 低到中 |

合成语料必须按**长度档位配额**（≤150 / ≤400 / ≤800 / >800），覆盖中英混
排、Markdown、URL、代码块、emoji、颜文字、超长文本。这一点在生成测试
用例时已踩过坑：LLM 默认产出 75% 的短文本，长文本路径等于没训。

### 5.2 合规与脱敏

- **授权**：训练数据必须来自授权范围。
- **PII 脱敏**：手机号、邮箱、地址、身份证、密钥、银行卡。
- **最小化**：只保留切分任务所需文本。
- **保留期限**：明确训练数据的保存周期。
- **出境评估**：使用外部 LLM API 时评估其数据政策。

### 5.3 标注格式（JSONL）

```json
{
  "id": "sample_001",
  "text": "原文...",
  "cuts": [15, 38, 52, 71],
  "cuts_protected": [14, 37, 51, 70],
  "source": "llm|rule|user|online",
  "confidence": "high|medium|low",
  "weight": 1.0,
  "group": "conversation_123",
  "split": "train"
}
```

- `cuts` 使用原文 Unicode 码点索引；`cuts_protected` 由坐标映射生成。
- `group` 用于分组划分，避免同一对话泄漏到不同 split。
- `weight` 用于训练加权，`confidence` 用于采样与损失加权。

### 5.4 数据划分

- 按 `group` 分组：同一对话只出现在一个 split。
- 时间外推验证：用旧数据训练，新数据验证。
- **金标测试集 300–500 条，人工双标**，计算 Kappa；**只从 `reviewed=true`
  里取，绝不允许合成数据进测试集**。
- 分层覆盖：中英混合、Markdown、URL、代码块、emoji、颜文字、超长文本。

### 5.5 质量控制

- LLM 合成：多次采样，投票保留高置信切分。
- 规则弱监督：人工盲审，标注者不知道哪条来自规则。
- 真实日志：只保留高置信信号，人工抽检。
- 在线反馈：只作弱标签或排序信号，不直接当二分类金标。
- **标注一致性 Kappa ≥ 0.8 才用于训练。**

**切分正确性不是二值的**：`我觉得吧。这个方案。` 与 `我觉得吧，这个方案。`
可能都对。因此标注给**主边界**，同时接受 ±1 个候选点的容差；评估用
「容差内 F1」，训练时容差内的候选也标为正例（软标签），避免把「同样
合理」的切点当负例打压。

### 5.6 标注成本 pilot（M1 的第一步）

在扩到 300–500 条之前先标 **50 篇**，测三件事：

1. **单篇耗时** —— 决定 300 篇是否现实（若 5 分钟/篇，300 篇 ≈ 25 小时）；
2. **多人一致性（Cohen's kappa）** —— 若两人一致性很低，说明标注协议
   本身有歧义，先改协议再扩量；
3. **与合成标签的差距** —— 量化「LLM 偏好 vs 人类偏好」的偏差，这是
   v3.0 最大的未知。

pilot 产出成本与一致性报告，据此复查第 11 章验收线与 gold set 规模。
**若 pilot 显示成本不可接受，应先回头调整任务定义，而不是硬扩数据量。**

### 5.7 数据飞轮

- 每周采样 500 条线上案例。
- 人工修正后进入训练集。
- 每月重训一次，评估后灰度。
- 错误案例按类型归档：候选漏召、语义边界、长度异常、特殊片段。

## 6. 候选点生成

候选生成由规则负责，目标是**宽召回**，宁多勿漏。

```python
def candidate_positions(protected, blocks):
    cands = set()
    cands |= positions_after_punctuation(protected)
    cands |= positions_after_space(protected)
    cands |= positions_after_newline(protected)
    cands |= markdown_block_boundaries(protected)
    cands |= url_code_formula_boundaries(protected)
    cands |= zh_en_boundaries(protected)
    cands |= number_unit_boundaries(protected)
    cands |= length_safety_points(protected, max_chars=60)
    cands = remove_inside_protected(cands, blocks)
    return sorted(cands)
```

**验收标准**：

- 在人工金标测试集上，**候选召回率 ≥ 99%**。
- **低于 99% 就先扩候选集，不训练模型。** 规则都没看见的位置，模型不
  可能学会切。
- 候选数量每 500 字控制在 30–80 个，避免特征爆炸。

> **与实测量对照**：现有 v2 的 `SEPS` 密度是 14.5 个/100 字，即
> **72.5 个/500 字**——已在上限附近。v3 的候选集比 v2 更大（新增中英边
> 界、数字单位边界、长度安全点），因此几乎肯定会**超出 30–80 这个上
> 限**。两个数字需要一起复查：要么放宽上限，要么承认特征爆炸风险并靠
> DP 打包来消化候选量。
>
> 另外，「14.5 个/100 字」只是**密度**，不是**召回率**。召回率必须先在
> 金标上实测——这是 M2 的第一件事，也是决定 v3 能否继续的门槛。

## 7. 特征工程

所有特征在**保护后坐标**上抽取。约 **55–65 维**。

### 7.1 局部字符特征（20 维）

- 前 1/2/3 字符类别 one-hot：汉字、字母、数字、标点、空白、emoji。
- 后 1/2/3 字符类别 one-hot。
- 当前字符标点类型：句末、句内、换行、空格、无。

### 7.2 位置与长度特征（8 维）

- `left_len`：距上一个候选点或段首长度。
- `right_len`：距下一个候选点长度。
- `cum_len`：距上一个已确认切点长度（训练用 gold，推理用模拟前缀）。
- `seg_pos`：段内相对位置。
- `is_first` / `is_last`。
- `is_near_max_chars`：是否接近长度上限。
- `is_after_long_segment`：左段是否偏长。

### 7.3 语义特征（10 维）

复用 v2 词表：前/后词是否中文尾坏点、中文头坏点、英文尾坏点、英文头坏
点、前词是否缩写、后词是否列表项开头、是否水平分割线、是否标题、左右
是否成对连词、是否语气词结尾。

### 7.4 结构特征（8 维）

`in_md_span`、`in_unclosed_bracket`、`in_url_or_code`、段落 id 相对位置、
是否跨段落、是否在表格内、是否在列表内、是否在引用块内。

### 7.5 候选上下文特征（6 维）

- 左邻候选点距离 / 右邻候选点距离。
- **左邻候选点模型分 / 右邻候选点模型分**（候选点之间互相参照）。
- 候选点密度。
- 是否连续标点。

> 这一组是相对 v2 的新增能力：它让模型看到「邻居怎么判」，而不只是当
> 前位置。代价是推理需要两遍（或按序一次前向填充），实现时要注意。

### 7.6 规则分数（4 维）

- `rule_score_norm`：v2 `score_cut` 归一化到 `[0,1]`。
- 规则子分：语义分、长度分、结构分。

> **把 v2 的规则判断作为特征喂给模型，而不是丢掉。** 这样模型在最坏情
> 况下也只是回到规则水平，不会更差——这是策略 A 的安全垫。

### 7.7 训练推理一致性

- 特征抽取函数**离线、在线共用同一份代码**（`qikou/features.py`，纯
  stdlib，随包分发；训练脚本直接 import 它，不复制代码）。
- 所有坐标先映射到保护后坐标。
- 缺失值统一填 `-1` 或中位数。
- 归一化参数保存到模型元数据，随模型一起版本化。

## 8. 模型与训练

### 8.1 模型选择与**复杂度预算**

首选 **LightGBM**：训练快、CPU 可完成、可解释（feature importance /
SHAP）、适合 5000+ 样本。

但树数 × 叶数就是纯 Python 推理的成本，必须当预算管：

| 配置 | 实测/推算推理成本 | 500 字（72 候选） |
|---|---|---|
| 100 树 × 15 叶 | 0.029 ms/候选 | **2.1 ms** |
| 200 树 × 31 叶 | 0.096 ms/候选（实测） | **6.9 ms** |
| 500 树 × 63 叶 | ≈ 0.5 ms/候选（推算） | ≈ 36 ms |
| **1000 树 × 63 叶** | ≈ 0.6 ms/候选（推算） | **≈ 42 ms** |

> ⚠️ **合并时发现的矛盾**：原方案给出 `num_leaves=63` /
> `num_boost_round=1000`，同时把推理目标写作「< 20ms/请求」。这两个数字
> 只有在**用 C++ 版 LightGBM 推理**时才自洽（原生约 0.001 ms/候选）。
> 一旦改用纯 Python 评估器以保住零依赖，同一模型的成本是 **约 42 ms**。
>
> **取舍建议**：默认路径把模型限制在 **≤ 200 树 × 31 叶**（6.9 ms/500
> 字，留出余量），先把质量做上去；如果精度必须靠更大模型才能达标，再二
> 选一：
> - (a) 放宽延迟目标到 ~50 ms（本地库调用，通常可以接受）；
> - (b) 提供可选加速档 `qikou[fast]`（引入 lightgbm），默认仍纯 Python。

**备选 Transformer**：数据量 > 5 万且 LightGBM 到瓶颈时再评估；ONNX 导
出，但那需要运行时依赖，属于上面 (b) 的范畴。

### 8.2 训练流程

```python
# 1. 加载数据，按 group 分组
X_train, y_train, groups_train = load_data("train.jsonl")
X_val, y_val, groups_val = load_data("val.jsonl")

# 2. 类别权重（实测正例率 10.9%）
pos_weight = (y_train == 0).sum() / (y_train == 1).sum()

# 3. LightGBM 训练
params = {
    "objective": "binary",
    "metric": "binary_logloss",
    "learning_rate": 0.05,
    "num_leaves": 31,          # 见 8.1 复杂度预算
    "min_data_in_leaf": 20,
    "feature_fraction": 0.8,
    "bagging_fraction": 0.8,
    "bagging_freq": 5,
    "scale_pos_weight": pos_weight,
    "verbose": -1,
}

dtrain = lgb.Dataset(X_train, y_train)
dval = lgb.Dataset(X_val, y_val, reference=dtrain)

model = lgb.train(
    params, dtrain,
    num_boost_round=200,       # 上限 200；早停更早则更省
    valid_sets=[dval],
    callbacks=[lgb.early_stopping(50), lgb.log_evaluation(50)],
)
```

### 8.3 分组交叉验证

- 使用 `GroupKFold`，按 `group` 划分。
- 避免同一对话的候选点同时出现在训练与验证集。
- 报告每折 F1、ECE、候选召回。

### 8.4 概率校准

- 训练后做 Platt scaling 或 isotonic calibration，校准集从验证集独立划分。
- 输出 `model_prob_calibrated`；阈值在验证集上选，不要拍 0.5。
- **产物必须可零依赖执行**：Platt 只需两个浮点数，isotonic 是一张阶梯
  表，都能用 JSON 表达。**不使用 `pickle`** —— 它既有安全风险，又要求
  加载端有相同的类定义。

### 8.5 模型注册与产物

注册信息：模型文件、特征列表与归一化参数、训练数据版本、校准参数、评
估报告、阈值配置。

导出为**零依赖产物**：

- 每棵树序列化为 5 个平行数组（`feat / thr / left / right / leaf`），
  节点用下标寻址。实测扁平化比字典版**快一倍**，加载仅 3 ms。
- 校准参数、特征列表、阈值、版本号放在同一 JSON 的元数据段。
- 体积目标：**< 250 KB**。

## 9. 推理与打包

### 9.1 零依赖推理（本方案的关键约束）

```python
def split_with_model(text, config):
    kaomoji.ensure_loaded()
    protected, blocks = protect_special(text)
    total = visible_len(protected, blocks)
    cfg = config.scaled_for_length(total)

    cands = candidate_positions(protected, blocks)
    if not cands:
        return [postprocess_message(restore_special(protected, blocks))]

    feats = [extract_features(protected, p, blocks, cands) for p in cands]
    probs = calibrate([model_score(f, model) for f in feats], model.meta)
    scores = fuse_scores(protected, cands, probs, cfg)
    cuts = dp_pack(protected, cands, scores, blocks, cfg)

    msgs, start = [], 0
    for cut in cuts:
        msgs.append(protected[start:cut].strip())
        start = cut
    msgs.append(protected[start:].strip())
    return [postprocess_message(restore_special(m, blocks)) for m in msgs]
```

`model_score` 是纯 Python 树遍历（`while` + 下标寻址，不用递归、不用字
典）。**已实测与 LightGBM 输出逐样本一致。**

### 9.2 动态规划打包

定义候选点 `p0 < p1 < ... < pn`，虚拟起点 `p_start`、虚拟终点 `p_end`。

`dp[i]`：以第 i 个候选点作为切点的最大总分。

```text
dp[j] = max(dp[i] + score(i, j))
```

其中：

- `score(i, j)` = 模型校准概率 + 规则分 − 长度惩罚 − 碎切惩罚。
- 长度约束：`j` 与 `i` 之间的可见长度落在 `min_chars` 到 `max_chars`。
- 若区间内没有候选点，强制在 `max_chars` 附近找最近的安全切点。

> DP 是对 v2 局部贪心的实质升级：贪心只看当前段，DP 能看到全局最优。
> 它**会改变输出**，因此必须作为独立里程碑做离线对比，不要和模型一起上线。

### 9.3 后处理

沿用 v2：合并过短消息、去除首尾空白、恢复特殊片段、保持 Markdown /
URL / 代码块完整、限制最大条数、补全未闭合标记。

### 9.4 回退机制

**模型层任何异常都必须回退到规则路径并记 warning，绝不让切分失败。**

回退触发条件：模型文件缺失、加载失败、元数据版本不符、特征维数不一致、
推理超时、出现 NaN / 异常概率。回退时记录原文哈希、模型版本、原因。

## 10. 融合策略

### 策略 A：规则主，模型做特征（v3.0 首发）

模型校准概率作为 `score_cut` 的加法项，系数在验证集上网格搜索：

```text
score = a * rule_score_norm + b * model_prob_calibrated
```

风险最低：最坏情况退回规则水平；复用全部现有后处理与打包逻辑，行为可
解释。代价是模型只能微调规则的取舍，跳不出规则的候选集。

### 策略 B：模型主，规则兜底

```text
if prob > high_threshold:
    cut = True
elif prob < low_threshold:
    cut = False
else:
    cut = rule_decision(...)
```

阈值从校准验证集选，不拍 0.5。

### 策略 C：模型决策，规则保结构

候选生成、特殊片段保护、打包、后处理仍由规则负责，切点决策完全交给模
型 + DP。数据量充足后启用。

**路径**：A → B → C，每步线上 A/B 对比。**v3.0 首发只走 A。**

## 11. 评估体系

### 11.1 离线指标

- **候选召回率**：金标切点被候选覆盖的比例，目标 ≥ 99%（进场门槛）。
- 切点 F1（精确率与召回率的调和平均）。
- **边界容忍 F1**：±1 / ±2 字符内算对。
- **完全一致率**：预测切分等于金标切分。
- 平均条数：与金标对比，判断偏碎或偏长。
- **校准 ECE**：概率校准误差。
- 分层错误分析：中英、Markdown、URL、代码、emoji、超长。
- **人工盲评**：v2 与 v3 成对比较。

### 11.2 线上指标

主指标：消息阅读完成率、用户滚动次数、重新询问率、复制率、对特定消息
的回复率。

护栏指标：端到端延迟 P95、推理错误率、回退规则路径比例、最大条数超限率。

### 11.3 A/B 测试

- 先做样本量与功效分析。
- 预注册主指标、护栏指标、分层维度。
- 50% v2 / 50% v3。
- 至少跑 2 周或达到统计显著。
- 分层看新用户/老用户、长文本/短文本、中文/中英混合。

### 11.4 验收线（v3.0 首发）

- gold 上端到端**边界 F1 ≥ 0.85**，且相对 v2 提升 ≥ 8 个百分点；
- **完全一致率 ≥ 60%**；
- 候选召回率 ≥ 99%；
- 推理新增耗时 ≤ 8 ms / 500 字（对应 ≤ 200 树 × 31 叶）；
- 包体积增量 ≤ 400 KB；
- 205 条既有用例的条数变化逐条人工确认（回归基线：报告正文哈希
  `F1E095F4F8FF3CA9`）。

## 12. 分阶段落地路径

| 阶段 | 周期 | 内容 | 退出标准 |
|---|---|---|---|
| **阶段 0：审计与基线** | 3–5 天 | 统计现有候选召回率；实现原文↔保护后坐标映射；建立 v2 在 gold 上的基线；合规评估 | 基线指标可复现；候选召回率有数 |
| **阶段 1：数据冷启动** | 1–2 周 | 抽 3000–5000 条历史回复并脱敏；LLM 多次采样投票生成切分；**先标 50 篇 pilot**；人工抽检；按 group 划分 | 3000+ 篇合成 + pilot 成本报告；Kappa ≥ 0.8 |
| **阶段 2：模型 alpha** | 1 周 | 特征工程 + LightGBM + 概率校准 + DP 打包 | 候选召回 ≥ 99%，切点 F1 > 0.85；策略 A 灰度 10% |
| **阶段 3：数据飞轮** | 2–4 周 | 线上隐式反馈弱标签化；每周采样 500 条人工修正；每月重训 | 指标持续改善；回退率 < 1% |
| **阶段 4：升级评估** | 1–2 月 | 线上显著优于 v2 后切策略 B；评估 DP 打包；数据 > 5 万且到瓶颈再评估 Transformer | A/B 复核通过 |
| **阶段 5：长期端到端** | 长期 | 候选生成可学习、打包可学习，形成「原文 → 切分」完整模型 | 留给 v4.0 |

## 14. 成本估算

| 项目 | 首次投入 | 持续成本 |
|---|---|---|
| LLM 合成数据 | $200–400 | — |
| 人工标注 | 30–50 小时 | 20–40 小时/月 |
| 训练算力 | 本机 CPU（实测 0.3 秒/次） | 每月 30 分钟 |
| 推理 | — | 2–7 ms/请求（纯 Python，≤200 树） |
| 工程 | 3–5 人周 | 维护 1–2 人天/月 |
| 合规与脱敏 | 1–2 人天 | 按需 |
| 监控与回退 | 2–3 人天 | 按需 |

总投入：约 2–3 人周 + $300，可产出初版并灰度。

**人工标注是最大成本项，且估得最不准**——这正是第 5.6 节要先做 50 篇
pilot 的原因。

## 15. 监控与回退

**监控指标**：请求量、延迟 P50/P95/P99、模型置信度分布、切分条数分布、
候选点数量分布、回退规则路径次数、异常概率 / NaN / 特征缺失、线上主指
标与护栏指标。

**回退条件**：模型加载失败、推理超时、特征抽取异常、回退率 > 1%、线上
主指标显著劣化。

**回退动作**：自动切回规则路径；记录原文哈希、模型版本、特征版本、错
误原因；告警通知；人工介入分析。

## 16. 风险

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| **合成标签 = LLM 偏好 ≠ 人类偏好** | 高 | 高 | 强制人工 gold set；test 只取 reviewed |
| 人工标注成本被低估 | 中 | 中 | 50 篇 pilot 先测耗时与 Kappa |
| 短文本合成偏置 | 高 | 中 | 生成时按长度档位配额，写进 Prompt |
| 切分正确性非二值，硬标签引入噪声 | 高 | 中 | 容差窗口 + 软标签 |
| **模型复杂度超推理预算** | 中 | 中 | 见 8.1；树数叶数当预算管，设上限 |
| 纯 Python 推理在超长文本上偏慢 | 中 | 低 | 只对 top-N 候选打分；或放宽延迟目标 |
| 候选集扩大后数量超过上限 | 中 | 中 | 用 DP 消化候选量；必要时分层裁剪 |
| DP 打包改变输出，引入回归 | 中 | 中 | 独立里程碑，单独离线对比 |
| 模型带来不可解释的回归 | 中 | 中 | `use_model=False` 始终可用；异常自动回退 |
| 特征训练/推理漂移 | 低 | 高 | 物理上共用 `qikou/features.py`，不复制代码 |
| 真实日志的合规问题 | 中 | 高 | 脱敏 + 授权 + 最小化 + 保留期限 |

---

## 17. 明确不做

- ❌ 不做端到端 Transformer（留给 v4.0，数据量 > 5 万再议）
- ❌ 不引入运行时第三方依赖（`numpy` / `lightgbm` 只在训练期）
- ❌ 不使用 `pickle` 作为模型产物格式
- ❌ 不把模型设为默认开启，直到 A/B 达标
- ❌ 不用模型去拟合 v2 的规则输出（那只是把规则蒸馏一遍，解决不了天花板）
- ❌ 不在 v3.0 首发同时上线模型与 DP 打包（两个变量一起动，出问题分不清）

## 18. 一句话总结

**v3.0 = 宽召回候选生成 + 统一坐标特征 + LightGBM 二分类 + 概率校准
+ 规则融合 + 动态规划全局打包 + 可监控可回退**，且**推理全程零第三方
依赖**。先走策略 A，再走 B，数据充分后走 C，把规则方案的天花板一步步
推高。
