# v3.0「韵律」设计方案（预研）

> 状态：预研完成，待评审
> 目标版本：v3.0
> 前置：v2.1（规则 + 打分，零依赖，205 用例）

---

## 0. TL;DR

v2.x 用规则 + 打分切分，天花板是**语义边界不等于标点边界**。v3.0 引入模型，但**不破坏零依赖**这个核心卖点：

> **训练用 LightGBM（开发期依赖），推理用随包分发的模型 + 纯 Python 评估器（运行时零依赖）。**

这条路线已在预研中实测验证：纯 Python 推理与 LightGBM 的输出**逐样本一致**（最大绝对差 1.1e-16），速度也够用。

---

## 1. 要解决的问题

规则方案有三类失败，README 已把它们列为「已知限制」。v3.0 只针对这三类，且每一类都要有可人工判定的标准：

| 失败模式 | 例子 | 期望 |
|---|---|---|
| 语义边界无标点 | `我觉得吧，这个方案，可能还需要再想想` | 在「吧」「方案」后断 |
| 超长句切在虚词后 | 英文切在 `to` / `and` 后，中文切在「的」「了」后 | 落在语义单元边界 |
| 语气 vs 信息 | `好吧。那就这样。` | 依语气决定一条还是两条 |

「对不对」由**人工标注的 gold set** 定义，不由规则定义——否则只是用模型去拟合旧规则。

---

## 2. 预研结论（实测数据）

在本机（Python 3.14 / LightGBM 4.7.0）实测：

| 项目 | 结果 |
|---|---|
| 候选点密度 | **14.5 个 / 100 字**（v2 的 `SEPS` 位置） |
| 弱标签正例率 | **10.9%**（约 1:8 不平衡） |
| 训练耗时 | 2 万行 × 40 特征、200 棵树 → **0.3 秒** |
| `dump_model()` | 可解析的 JSON，树结构为 `split_feature` / `threshold` / `left_child` / `right_child` |
| **纯 Python 推理精度** | 与 `booster.predict()` 最大绝对差 **1.1e-16**（即逐样本一致） |
| 纯 Python 推理速度 | 0.191 ms/候选（朴素字典版）→ **0.096 ms/候选**（扁平数组版，200 树 × 31 叶） |
| 换算 | 500 字（约 72 候选）**6.9 ms**；1000 字约 13.9 ms |
| 折半模型 | 100 树 × 15 叶 ≈ **0.029 ms/候选** → 500 字约 **2.1 ms** |
| 模型体积 | 397 KB（200×31）→ 约 200 KB（100×15） |
| **现有语料可用性** | `tests/test.txt` 中位长度仅 **12 字**，是测试集不是训练集，**必须另建语料** |

结论：**技术路线可行，主要风险不在工程，在数据。**

## 3. 核心架构决策

### 3.1 训练与推理解耦：模型进包，依赖不进包

```
训练期（开发机）                     运行期（用户机器）
─────────────────                  ─────────────────
语料 JSONL                          pip install qikou
   ↓                                   ↓
qikou.features 提特征               qikou/model.json（随包）
   ↓                                   ↓
LightGBM 训练                       qikou/model.py（纯 Python 评估器）
   ↓                                   ↓
booster.dump_model()  ──序列化──→   qikou.features 提同一批特征
   ↓                                   ↓
紧凑 JSON 产物                      切点打分
```

- **不引入 `lightgbm` / `numpy` 到运行时依赖**，`pip install qikou` 依然只装一个纯 Python 包。
- 模型产物是**扁平的平行数组**（`feat/thr/left/right/leaf`），加载 3 ms、体积最小，避免 JSON 字典的解析与查询开销。实测扁平化比字典版快一倍。

### 3.2 特征代码只有一份

`qikou/features.py`（纯标准库，**随包分发**）同时被训练脚本 import。

这是防止「训练-推理特征漂移」的唯一可靠做法：不复制代码、不靠约定，而是让两边物理上引用同一个模块。训练脚本用 `sys.path` 指向仓库根即可。

### 3.3 模型是可选的、可回退的

```python
Config(use_model=False)   # v3.0 默认关，A/B 达标后才考虑默认开
```

模型层任何异常（文件缺失、版本不符、特征数不一致）都必须**回退到 v2 规则路径**并记一条 warning，绝不让切分失败。

### 3.4 目录结构

```
qikou/
├── features.py          # 特征提取（纯 stdlib，随包）
├── model.py             # 纯 Python GBM 评估器 + 加载（随包）
├── model.json           # 模型产物（随包，与 kaomojis.txt 同级）
├── splitter.py          # 规则路径 + 融合点
└── ...                  # 其余不变

training/                # 训练管线，不进 wheel（MANIFEST + packages 排除）
├── generate.py          # LLM 合成语料
├── annotate.py          # 标注/转换工具
├── features_dump.py     # 用 qikou.features 批量提特征
├── train.py             # LightGBM 训练 → model.json
├── eval.py              # 评估与 A/B
└── data/*.jsonl
```

> 注意：模型文件放在**包根目录**而不是 `qikou/models/`。上一版打包时踩过坑——`qikou/data/` 这种没有 `__init__.py` 的子目录会被 setuptools 当成命名空间包并报 warning。

## 4. 数据方案（最大风险项）

### 4.1 来源与规模

| 来源 | 规模 | 作用 |
|---|---|---|
| LLM 合成 | 3000–5000 篇 | 主力，覆盖长度档位 / 语言 / 结构 |
| 真实脱敏语料 | 200–500 篇 | 修正合成数据的分布偏置 |
| 规则弱监督 | 全量 | 预标注（v2 的切点作为初始标签，人工只改错） |
| **人工 gold set** | **先 50 篇 pilot，再定规模** | **唯一可信的评估基准**，必须人工逐篇确认 |

合成语料的关键要求：**长度档位必须覆盖 v2 的四档**（≤150 / ≤400 / ≤800 / >800），否则长文本路径等于没训。这一点在上一轮生成测试用例时已经暴露过——LLM 默认会生成 75% 的短文本。

### 4.2 标注协议

人工只需标注**理想气泡边界**（字符偏移列表），不标「不可切点」——负例由候选点自动推导。

**容差窗口**：切分正确性不是二值的。`我觉得吧。这个方案。` 与 `我觉得吧，这个方案。` 可能都对。因此：

- 标注给出**主边界**，同时接受 ±1 个候选点的容差；
- 评估用「容差内 F1」，而不是精确匹配；
- 训练时把容差内的候选也标为正例（软标签），避免把「同样合理」的切点当负例打压。

### 4.3 格式（JSONL）

```json
{"id":"syn-000123","text":"……","cuts":[11,38,52],"tier":2,
 "source":"llm","annotator":"gpt-x","reviewed":false}
```

- `cuts`：切点字符偏移，升序
- `tier`：长度档位 1–4（便于分层抽样与分层评估）
- `reviewed`：是否经过人工确认（gold set 为 true）

### 4.4 数据划分

按 `source` 分层抽 8:1:1 为 train/dev/test。**test 只从 `reviewed=true` 里取**；绝不允许合成数据进 test。

### 4.5 标注成本 pilot（M1 的第一步）

在扩到 300 篇之前先标 50 篇，测三件事：

1. **单篇耗时** —— 决定 300 篇是否现实（若 5 分钟/篇，300 篇 ≈ 25 小时）；
2. **多人一致性（Cohen's kappa）** —— 若两人一致性很低，说明标注协议本身有歧义，先改协议再扩量；
3. **与合成标签的差距** —— 量化「LLM 偏好 vs 人类偏好」的偏差，这是 v3.0 最大的未知。

pilot 的产出是一份成本与一致性报告，据此复查第 8 章的验收线与 gold set 规模。**若 pilot 显示成本不可接受，应先回头调整任务定义，而不是硬扩数据量。**

## 5. 特征清单（40 维草案）

| 组 | 维数 | 内容 |
|---|---|---|
| A 局部字符 | 12 | 切点左/右各 3 字符的类别（CJK / 拉丁 / 数字 / 空白 / 标点 / emoji / 颜文字 / 零宽）；左侧是否为句末标点、逗号、冒号、分号；右侧是否为首字符 |
| B 词表 | 8 | 英文缩写命中；中文尾坏词（因为/虽然…）；中文头坏词（所以/但是…）；英文尾坏词；英文头坏词；右邻是否列表项；词边界（左右是否都是字母数字） |
| C 位置与长度 | 6 | 切点绝对位置、相对位置、距句首长度、距句尾长度、当前累积长度、累积长度 / `target_chars` |
| D 结构状态 | 6 | 是否在代码块内、是否在 Markdown span 内、未闭合括号深度、是否在未闭合引号内、是否在表格内、是否在引用块内 |
| E 规则分 | 4 | v2 `score_cut` 的基础分、加完修正后的总分、`find_cut` 是否选中该点、该点的排名分位 |
| F 语言与混排 | 4 | 文本主语言、中英混排比例、是否含 RTL 字符、标点全半角比例 |

> E 组是关键：把 v2 的规则判断**作为特征喂给模型**，而不是丢掉。这样模型在最坏情况下也只是回到规则水平，不会更差——这就是策略 A 的安全垫。

## 6. 模型与训练

| 项 | 取值 | 理由 |
|---|---|---|
| 目标 | `binary` | 候选点二分类 |
| `num_leaves` | 15–31 | 越大越容易过拟合小数据 |
| `num_boost_round` | 100–200，早停 | 纯 Python 推理成本与树数线性相关 |
| `min_data_in_leaf` | 40+ | 抑制噪声标签 |
| 不平衡 | `scale_pos_weight ≈ 8` | 实测正例率 10.9% |
| 特征数 | 40 | 与推理端一致，由 `qikou/features.py` 保证 |

产物序列化为扁平 JSON：每棵树 5 个平行数组，节点用下标寻址。

## 7. 融合策略（分两步走）

### 策略 A：模型做特征，规则做主（v3.0 首发）

候选点仍由 v2 的 `SEPS` 生成；规则照旧打分，但把**模型预测概率作为一个修正项**加进 `score_cut`。

- 风险最低：最坏情况退回规则水平；
- 复用全部现有后处理与打包逻辑，切分行为可解释；
- 代价：模型只能微调规则的取舍，无法跳出规则的候选集。

### 策略 B：模型做主（v3.1）

模型直接决定切点，规则只负责候选生成 + 打包 + 后处理收尾。

- 能解决「规则根本没给出候选」的情况；
- 风险高，需要 A 阶段积累的 A/B 数据支撑。

**打包、合并、后处理三块在 v3.0 完全不动**——它们与「切点选得对不对」是正交问题。

## 8. 评估方案

| 层级 | 指标 | 基线 |
|---|---|---|
| 候选层 | PR-AUC、切点 F1（容差 ±1 候选） | v2 规则分 |
| 端到端 | 与 gold 的边界 F1、**完全一致率**、平均条数偏差、单条长度分布 | v2.0 |
| 回归 | 205 个既有用例：条数变化清单，人工逐条确认 | 当前输出（正文哈希 F1E095F4F8FF3CA9） |
| 上限 | 多人独立标注的一致性（Cohen's kappa） | 用来判断「模型离人类还有多远」 |

**验收线（草案，待评审）**：
- gold 上端到端边界 F1 相对 v2 提升 ≥ 8 个百分点；
- 完全一致率 ≥ 60%；
- 推理新增耗时 ≤ 8 ms / 500 字；
- 包体积增量 ≤ 400 KB。

## 11. 风险

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| **合成标签 = LLM 偏好 ≠ 人类偏好** | 高 | 高 | 强制人工 gold set；test 只取 reviewed |
| 人工标注成本被低估 | 中 | 中 | 先做 50 篇小样本，测标注耗时再决定规模 |
| 短文本合成偏置（v2 已踩过） | 高 | 中 | 生成时就按长度档位配额，写进 Prompt |
| 切分正确性非二值，硬标签引入噪声 | 高 | 中 | 容差窗口 + 软标签 |
| 纯 Python 推理在超长文本上偏慢 | 中 | 低 | 树数/叶数可调；必要时只对 top-N 候选打分 |
| 模型带来不可解释的回归 | 中 | 中 | `use_model=False` 始终可用；异常自动回退 |
| 特征训练/推理漂移 | 低 | 高 | 物理上共用 `qikou/features.py`，不复制代码 |

## 12. 明确不做

- ❌ 不做端到端 Transformer（留给 v4.0，数据量 > 5 万再议）
- ❌ 不引入运行时第三方依赖（`numpy` / `lightgbm` 只在训练期）
- ❌ 不修改打包、合并、后处理逻辑（正交问题）
- ❌ 不把模型设为默认开启，直到 A/B 达标
- ❌ 不用模型去拟合 v2 的规则输出（那只是把规则蒸馏一遍，解决不了天花板）
