# v3.0 优化版完整方案

## 1. 目标与设计原则

**目标**：在 v2.0 规则方案基础上，引入候选点二分类模型，把切分质量从规则上限推进到 90+，同时保持低风险、可解释、可回退。

**设计原则**：

1. **规则保底，模型增强**：候选生成、特殊片段保护、后处理仍由规则负责；模型只决定“切不切”。
2. **坐标统一**：原文坐标、保护后坐标、切点标签、特征抽取全部使用同一套映射。
3. **候选宽召回**：候选点生成宁多勿漏，目标候选召回率 ≥ 99%。
4. **概率校准**：模型输出必须校准后再用于融合和阈值判断。
5. **全局打包**：推理阶段用动态规划或 beam search，替代局部贪心。
6. **可回退可监控**：线上异常自动回退 v2.0，模型、特征、数据均有版本记录。
7. **合规先行**：真实聊天日志必须脱敏、授权、最小化使用。

## 2. 总体架构

### 离线管线

```
原始语料
  → 脱敏与合规过滤
  → 坐标映射与保护片段
  → 候选点生成
  → 特征抽取
  → 标签对齐
  → LightGBM 训练
  → 概率校准
  → 离线评估
  → 模型注册
```

### 在线管线

```
用户输入
  → protect_special + 坐标映射
  → 候选点生成
  → 特征抽取
  → 模型预测
  → 概率校准
  → 规则融合
  → 动态规划打包
  → 后处理
  → 输出多条消息
  → 监控与回退
```

## 3. 任务建模

**核心任务**：候选点二分类 + 全局切分决策。

- 输入：一段 Agent 回复文本。
- 候选点：所有可能切分的位置。
- 模型输出：每个候选点的校准切分概率。
- 最终决策：在长度约束、语义约束、规则分数下，用动态规划选出全局最优切分序列。

**候选点定义**：

- 标点后：。！？!?…；;，,、：:
- 空格后、换行后
- Markdown 块边界：标题、列表项、引用、代码块结束
- URL、代码块、行内代码、公式外边界
- 中英边界、数字/单位边界
- 长度安全点：每 `max_chars` 附近最近空格或标点

**标签定义**：

- 正样本：候选点属于人工/LLM 金标切点。
- 负样本：候选点不属于金标切点。
- 所有标签必须映射到保护后坐标，再与候选点比较。

## 4. 数据方案

### 4.1 数据来源分层

| 层级 | 来源 | 用途 | 置信度 |
|---|---|---|---|
| L1 | LLM 合成切分 | 冷启动 | 中高 |
| L2 | 规则弱监督 + 人工修正 | 快速扩量 | 中 |
| L3 | 真实聊天日志挖掘 | 贴近真实分布 | 高 |
| L4 | 在线隐式反馈 | 持续优化 | 低到中 |

### 4.2 合规与脱敏

- 用户授权：训练数据必须来自授权范围。
- PII 脱敏：手机号、邮箱、地址、身份证、密钥、银行卡。
- 数据最小化：只保留切分任务所需文本。
- 保留期限：明确训练数据保存周期。
- 出境评估：使用外部 LLM API 时评估数据政策。

### 4.3 标注格式

统一 JSONL：

```json
{
  "id": "sample_001",
  "text": "原文...",
  "cuts": [15, 38, 52, 71],
  "cuts_protected": [14, 37, 51, 70],
  "source": "llm|rule|user|online",
  "confidence": "high|medium|low",
  "weight": 1.0,
  "group": "conversation_123",
  "split": "train"
}
```

说明：

- `cuts` 使用原文 Unicode 码点索引。
- `cuts_protected` 由坐标映射生成。
- `group` 用于分组划分，避免同一对话泄漏。
- `weight` 用于训练加权。
- `confidence` 用于采样和损失加权。

### 4.4 数据划分

- 按 `group` 分组，同一对话只出现在一个 split。
- 时间外推验证：用旧数据训练，新数据验证。
- 保留金标测试集：至少 300–500 条，人工双标，计算 Kappa。
- 分层覆盖：中英混合、Markdown、URL、代码块、emoji、颜文字、超长文本。

### 4.5 质量控制

- LLM 合成：多次采样，投票保留高置信切分。
- 规则弱监督：人工盲审，不知道哪条来自规则。
- 真实日志：只保留高置信信号，人工抽检。
- 在线反馈：只作为弱标签或排序信号，不直接当二分类金标。
- 标注一致性：Kappa ≥ 0.8 才用于训练。

### 4.6 数据飞轮

- 每周采样 500 条线上案例。
- 人工修正后进入训练集。
- 每月重训一次，评估后灰度。
- 错误案例按类型归档：候选漏召、语义边界、长度异常、特殊片段。

## 5. 候选点生成

候选生成由规则负责，目标是宽召回。

```python
def candidate_positions(protected, blocks):
    cands = set()
    cands |= positions_after_punctuation(protected)
    cands |= positions_after_space(protected)
    cands |= positions_after_newline(protected)
    cands |= markdown_block_boundaries(protected)
    cands |= url_code_formula_boundaries(protected)
    cands |= zh_en_boundaries(protected)
    cands |= number_unit_boundaries(protected)
    cands |= length_safety_points(protected, max_chars=60)
    cands = remove_inside_protected(cands, blocks)
    return sorted(cands)
```

验收标准：

- 在人工金标测试集上，候选召回率 ≥ 99%。
- 如果低于 99%，先扩候选集，不训练模型。
- 候选点数量控制在每 500 字 30–80 个，避免特征爆炸。

## 6. 特征工程

所有特征在保护后坐标上抽取。特征约 55–65 维。

### 6.1 局部字符特征（20 维）

- 前 1/2/3 字符类别 one-hot：汉字、字母、数字、标点、空白、emoji。
- 后 1/2/3 字符类别 one-hot。
- 当前字符标点类型：句末、句内、换行、空格、无。

### 6.2 位置与长度特征（8 维）

- `left_len`：距上一个候选点或段首长度。
- `right_len`：距下一个候选点长度。
- `cum_len`：距上一个已确认切点长度，训练时用 gold 或模拟前缀。
- `seg_pos`：段内相对位置。
- `is_first`、`is_last`。
- `is_near_max_chars`：是否接近长度上限。
- `is_after_long_segment`：左段是否偏长。

### 6.3 语义特征（10 维）

复用 v2.0 词表：

- 前词是否中文尾坏点。
- 后词是否中文头坏点。
- 前词是否英文尾坏点。
- 后词是否英文头坏点。
- 前词是否缩写。
- 后词是否列表项开头。
- 是否水平分割线。
- 是否标题。
- 左右是否成对连词。
- 是否语气词结尾。

### 6.4 结构特征（8 维）

- `in_md_span`
- `in_unclosed_bracket`
- `in_url_or_code`
- 段落 id 相对位置
- 是否跨段落
- 是否在表格内
- 是否在列表内
- 是否在引用块内

### 6.5 候选上下文特征（6 维）

- 左邻候选点距离。
- 右邻候选点距离。
- 左邻候选点模型分。
- 右邻候选点模型分。
- 候选点密度。
- 是否连续标点。

### 6.6 规则分数（1 维）

- `rule_score_norm`：v2.0 `score_cut` 归一化到 [0,1]。
- 可附加多个规则子分：语义分、长度分、结构分。

### 6.7 训练推理一致性

- 特征抽取函数离线、在线共用。
- 所有坐标先映射到保护后坐标。
- 缺失值统一填 -1 或中位数。
- 归一化参数保存到模型元数据。

## 7. 模型与训练

### 7.1 模型选择

首选 LightGBM：

- 训练快，CPU 可完成。
- 推理延迟低。
- 可解释，feature importance / SHAP。
- 适合 5000+ 样本。

备选 Transformer：

- 当数据量 > 5 万且 LightGBM 达到瓶颈时考虑。
- 输入字符序列 + 特征 embedding。
- ONNX 导出，推理约 20–50ms。

### 7.2 训练流程

```python
# 1. 加载数据，按 group 分组
X_train, y_train, groups_train = load_data("train.jsonl")
X_val, y_val, groups_val = load_data("val.jsonl")

# 2. 类别权重
pos_weight = (y_train == 0).sum() / (y_train == 1).sum()

# 3. LightGBM 训练
params = {
    "objective": "binary",
    "metric": "binary_logloss",
    "learning_rate": 0.05,
    "num_leaves": 63,
    "min_data_in_leaf": 20,
    "feature_fraction": 0.8,
    "bagging_fraction": 0.8,
    "bagging_freq": 5,
    "scale_pos_weight": pos_weight,
    "verbose": -1,
}

dtrain = lgb.Dataset(X_train, y_train)
dval = lgb.Dataset(X_val, y_val, reference=dtrain)

model = lgb.train(
    params,
    dtrain,
    num_boost_round=1000,
    valid_sets=[dval],
    callbacks=[lgb.early_stopping(50), lgb.log_evaluation(50)],
)
```

### 7.3 分组交叉验证

- 使用 `GroupKFold`，按 `group` 划分。
- 避免同一对话的候选点同时出现在训练和验证集。
- 报告每折 F1、ECE、候选召回。

### 7.4 概率校准

- 训练后做 Platt scaling 或 isotonic calibration。
- 校准集从验证集独立划分。
- 输出 `model_prob_calibrated`。
- 阈值在验证集上选，不拍 0.5。

### 7.5 模型注册

保存：

- 模型文件
- 特征列表与归一化参数
- 训练数据版本
- 校准参数
- 评估报告
- 阈值配置

## 8. 推理与打包

### 8.1 推理流程

```python
def split_with_model(text, cfg):
    protected, blocks, orig_to_prot = protect_special_with_map(text)
    total = visible_len(protected, blocks)
    cfg.scale_for_length(total)

    cands = candidate_positions(protected, blocks)
    if not cands:
        return [restore_special(protected, blocks)], cfg

    feats = [extract_features(protected, p, blocks, cands) for p in cands]
    probs = model.predict(feats)
    probs = calibrate(probs)

    scores = fuse_scores(protected, cands, probs, cfg)

    cuts = dp_pack(protected, cands, scores, blocks, cfg)

    msgs = []
    start = 0
    for cut in cuts:
        msgs.append(protected[start:cut].strip())
        start = cut
    msgs.append(protected[start:].strip())

    out = [restore_special(m, blocks) for m in msgs]
    out = [postprocess_message(m) for m in out]
    return out, cfg
```

### 8.2 动态规划打包

定义候选点 `p0 < p1 < ... < pn`，虚拟起点 `p_start`，虚拟终点 `p_end`。

`dp[i]`：以第 i 个候选点作为切点的最大总分。

转移：

```text
dp[j] = max(dp[i] + score(i, j))
```

其中：

- `score(i, j)` = 模型校准概率 + 规则分 - 长度惩罚 - 碎切惩罚。
- 长度约束：`j` 与 `i` 之间可见长度在 `min_chars` 到 `max_chars` 之间。
- 若没有候选点，强制在 `max_chars` 附近找最近安全切点。

### 8.3 后处理

沿用 v2.0：

- 合并过短消息。
- 去除首尾空白。
- 恢复特殊片段。
- 保持 Markdown、URL、代码块完整。
- 限制最大条数。

### 8.4 回退机制

- 模型文件缺失、加载失败、推理超时、异常概率 → 回退 v2.0。
- 回退率超过阈值告警。
- 每次回退记录原文哈希、模型版本、原因。

## 9. 融合策略

### 策略 A：规则主，模型做特征

- 模型校准概率作为 `score_cut` 的加法项。
- 公式在验证集网格搜索：

```text
score = a * rule_score_norm + b * model_prob_calibrated
```

- `a`、`b` 离线确定。
- 适合初期灰度，风险最低。

### 策略 B：模型主，规则兜底

- 模型概率高置信时直接采用。
- 低置信区间用规则决策。
- 阈值从校准验证集选。

```text
if prob > high_threshold:
    cut = True
elif prob < low_threshold:
    cut = False
else:
    cut = rule_decision(...)
```

### 策略 C：模型决策，规则保结构

- 候选生成、特殊片段保护、后处理仍由规则负责。
- 切点决策完全交给模型 + DP。
- 数据量充足后启用。

**路径**：A → B → C，每步线上 A/B 对比。

## 10. 评估体系

### 10.1 离线指标

- 候选召回率：金标切点被候选覆盖比例，目标 ≥ 99%。
- 切点 F1：精确率与召回率调和平均。
- 边界容忍 F1：±1/±2 字符内算对。
- 完全一致率：预测切分等于金标切分。
- 平均条数：与金标对比，判断偏碎或偏长。
- 校准 ECE：概率校准误差。
- 分层错误分析：中英、Markdown、URL、代码、emoji、超长。
- 人工盲评：v2.0 vs v3.0 成对比较。

### 10.2 线上指标

主指标：

- 消息阅读完成率。
- 用户滚动次数。
- 重新询问率。
- 复制率。
- 对特定消息的回复率。

护栏指标：

- 端到端延迟 P95。
- 推理错误率。
- 回退 v2.0 比例。
- 最大条数超限率。

### 10.3 A/B 测试

- 先做样本量与功效分析。
- 预注册主指标、护栏指标、分层维度。
- 50% v2.0，50% v3.0。
- 至少跑 2 周或达到统计显著。
- 分层看新用户/老用户、长文本/短文本、中文/中英混合。

## 11. 分阶段落地路径

### 阶段 0：审计与基线（3–5 天）

- 统计候选召回率。
- 实现坐标映射。
- 建立 v2.0 独立测试集基线。
- 合规评估。
- 120 用例回归测试。

### 阶段 1：数据冷启动（1–2 周）

- 抽 3000–5000 条历史回复，脱敏。
- LLM 多次采样，投票生成切分。
- 人工抽检 300–500 条，计算 Kappa。
- 规则弱监督 + 人工修正。
- 按 group 划分训练/验证/测试。

### 阶段 2：模型 alpha（1 周）

- 特征工程 + LightGBM。
- 概率校准。
- 动态规划打包。
- 离线目标：候选召回 ≥ 99%，切点 F1 > 0.85。
- 融合策略 A，10% 流量灰度。

### 阶段 3：数据飞轮（2–4 周）

- 线上隐式反馈弱标签化。
- 每周采样 500 条人工修正。
- 每月重训，灰度发布。
- 监控漂移与回退率。

### 阶段 4：升级评估（1–2 月）

- 若线上显著优于 v2.0，切策略 B。
- 若数据量 > 5 万且 LightGBM 瓶颈，评估 Transformer。
- 持续优化候选生成与打包算法。

### 阶段 5：长期端到端

- 候选生成可学习。
- 打包策略可学习。
- 最终形成“原文 → 切分”完整模型。

## 14. 监控与回退

监控指标：

- 请求量、延迟 P50/P95/P99。
- 模型置信度分布。
- 切分条数分布。
- 候选点数量分布。
- 回退 v2.0 次数。
- 异常概率、NaN、特征缺失。
- 线上主指标与护栏指标。

回退条件：

- 模型加载失败。
- 推理超时。
- 特征抽取异常。
- 回退率超过 1%。
- 线上主指标显著劣化。

回退动作：

- 自动切回 v2.0。
- 记录原文哈希、模型版本、特征版本、错误原因。
- 告警通知。
- 人工介入分析。
